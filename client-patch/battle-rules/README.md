# 通用回槽限制与伤害类型转换

本补丁只生成候选。静态检查与 APK 验签不代表已安装或通过实机战斗验收。
基线锁定在 `patch.py` 的完整 SWF SHA-256；使用原指令插入方式，禁止 AS3 全量回编。
构建报告验证所有既有指令可还原、无关方法及 APK 资源保持不变。

循环入口必须同时定义汇编符号标签和 `avm_label`（真实 AVM2 `0x09` 指令）。
单独的 `('label', 'LOOP')` 不输出字节；反向跳转到普通指令会使 AIR 在首次调用时
报 `VerifyError #1021`。v2 的空规则数组也会触发该验证错误，表现为开战黑屏；
v3 已修复回槽筛选和伤害转换规则的两个循环，构建器会拒绝再次生成这种方法。

## 回槽限制

能力表持续内容 `423`，目标沿用原生目标列：自身、其他角色、全队、指定位置；
全队与其他角色还可通过角色组限定属性。`c118` 保存整数规则码，不乘 100000。
配置函数见 `mod-tools/wf_battle_rules.py` 的 `gauge_mask`、`make_row`。

| 筛选组 | 可选来源 |
| --- | --- |
| 加槽方式 | 开场、移动跑条、技能直接回槽、能力回槽、连击触发的能力、施技触发的能力、其他动作脚本 |
| 效果出处 | 角色能力／技能、队长技、武器含觉醒能力、能力魂、EX |
| 效果持有者 | 收槽角色自己、其他角色 |
| 触发角色 | 收槽角色自己、其他角色 |

组内任选其一，组间必须同时满足。能力回槽包括连击和施技触发的子类；要只禁其中一类，
仅选择该子类。两类角色关系分开判断，不能把“自身能力由队友技能触发”误认成队友直接给槽。
无法追溯触发者的原生事件保留未知，不假定为自己或队友。
自身／其他角色关系以原生作战位置判定，同位置主副位共享技能槽。
出处筛选区分武器这一类，不区分某一把武器 ID；原生道具拾取及复活奖励不属于技能／能力回槽。

```python
gauge_mask(['skill', 'ability'])                 # 月兔风：12，开场及移动保留
gauge_mask(['ability'], origins=['weapon'])     # 只禁武器战斗回槽
gauge_mask(['skill'], owners=['other'])         # 只禁其他角色技能直接给槽
gauge_mask(['skill_triggered_ability'], owners=['self'], triggers=['other'])
gauge_mask(['combo_ability'])                   # 只禁连击触发的能力回槽
gauge_mask(['movement'])                        # 禁止正常跑条，单列规则
```

在入账/排队时拦截正向增加；不改技能耗槽、负向扣槽，不对已获准的队列重复过滤。
开场技能槽比例及开场能力另有标签。自然跑条没有武器持有者等来源，不接受这类混合筛选。
629 自动追加施放本身不消耗技能槽，回槽限制不会禁止它；月兔风原有连击和自动追加技能保留。
原生技能队列的异步动作保存来源快照，后续触发不能篡改已创建动作的来源。

无效回槽在 `MemberImpl.applyInstantAbility` 的目标演出前过滤：原先先创建
`AbilityPerpetuity` 再在 reserve 入口拒绝入账，大量连击触发时仍会积累逐帧更新的无效特效。
现在仅对实际正向的比例／固定回槽提前返回，保留触发次数、冷却、零值及扣槽；
同步检查直接读取已有来源地址，并在继续或返回前恢复外层上下文。
规则先匹配来源位，再求活动条件，避免正常移动时查询不相关的回槽限制。
不缓存跨帧条件，不合并触发器调用；实机帧率仍需用原掉帧队伍复测。

`gauge_perf_overlay.py` 锁定 1.4.1043 汇总包 SWF，仅替换这两处方法，
保留其中的伤害类型转换、语音池及其他修复。输出为待实测候选，不自动安装。

## 伤害类型

支持普通伤害对象的技能、能力、直击、PF1／PF2／PF3 之间转换。

- 单个动作或判定区：`buffTargetAs` 用 `101` 技能、`102` 能力、`104` 直击、`131..133` PF1..3。
- 整个角色：能力持续内容 `424`，`c118 = 来源×100 + 目标`；用 `damage_rule` 编码。
  来源为 `any/skill/ability/power_flip/direct`，目标为 `skill/ability/direct/pf1/pf2/pf3`。
- 单段配置优先；角色规则按首个活动匹配规则，只转换一次，禁止来回循环。
- 转换普通增伤、对应独立乘区、来源标志和 PF 分档；保留原技能动作、视觉、倍率和命中次数。
  这不等于触发一次新的技能施放或实际 PF 发射事件。
- 固定伤害、比例伤害、无伤害状态和已经写入基础倍率的分段系数不在转换范围。

澄波响只给队长触发的追加攻击设置 `133`，固定 PF3 分类；原 PF 三档和主动技能保持。
凯尔等其他角色尚未写入新转换规则，不会全局变更。

DSL 标记须先经过 `Environment.getBuffTargetAs`：v4 为它添加了上述六个显式值的通路，
并保留 `0` 继承父环境、原生 `1..4` 局部覆盖的行为。只在 NormalAttack 处转换还不够：
原版 getter 会丢弃 `133` 等未知值，最终仍按技能结算和显示。回归测试直接执行原 getter
及补丁后的字节码，覆盖嵌套继承、局部覆盖、非法值与最终 PF3 分类。

## 数据兼容与构建

423／424 **仅扩展 ability 表解析器**。武器作为被筛选的回槽来源可以识别，
但当前不能把新 423／424 词条直接写入武器、队长或 EX 表；工具会拒绝。
能力效果本身可以作用于全队，足以支持全队限制。

`gauge-gain-rules-v1` 与 `damage-type-rules-v1` 是候选能力声明，不能冒充设备已安装记录。
没有兼容客户端时不得把 423／424 发布到 live，否则旧 APK 读表会报错。
`stage_characters.py` 在仓外建立隔离角色候选，保留原活动包和当前链。

```powershell
python -X utf8 client-patch/battle-rules/patch.py <原SWF> <新SWF> --report <新报告.json>
python -X utf8 client-patch/battle-rules/build_apk.py --help
python -X utf8 -m unittest discover -s client-patch/battle-rules/tests -p 'test_*.py'
```

APK 构建必须使用与基线相同的签名证书，口令仅通过环境变量传递。
运行时验收还需：开场充能、移动充能、己方／队友技能／武器回槽、连击回槽、阵亡与复活、
全队与属性目标、澄波响 PF3 普通及独立加成、跨设备联机一致性。安装须有作者明确指示。

## 覆盖安装后的实际程序核对

同签名 `pm install -r` 可能保留 AIR 在 `cache/app/<uuid>/assets/` 解包的旧 SWF。
发布 423／424 数据前，除了回读安装的 APK，还必须核对该运行缓存的 SWF SHA-256
与构建报告一致。旧缓存会让编队页在 `AbilityValues.parseAt109` 报 C7050。
若不一致，停止已确认的游戏进程，将 **仅 `com.leiting.wf/cache/app`** 改名备份，
再启动客户端让它从新 APK 解包；不清空应用数据或资源下载目录，不卸载。
等待旧进程完全退出后再启动，并回读新缓存哈希、检查编队页。安装或刷新程序缓存仍需作者授权。
