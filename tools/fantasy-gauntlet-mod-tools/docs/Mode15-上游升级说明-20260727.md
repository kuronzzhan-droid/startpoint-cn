## Mode15 的本地差异

### 路径固定

`profiles.json` 已明确配置：

```json
{
  "cdn_dir": "F:/codex/mode15-work/isolated-server/.cdn/cn",
  "server_dir": "F:/codex/mode15-work/isolated-server"
}
```

不要把它们改成 `F:\startpoint-cn-main` 或其他共享项目。

### 版本上限

`wf_publish.py` 默认禁止自动越过 `1.4.59`。从 `1.4.59` 再发布会拒绝生成
`1.4.60`。只有在明确批准新客户端版本后，才允许临时设置：

```powershell
$env:WF_MAX_PUBLISH_VERSION = "1.4.60"
```

未批准时不要设置该变量。

### dev 功能默认关闭

为了保持当前旧客户端发布行为，下列功能默认不启用：

- medium/android 无内容层的 `.empty` 占位包；
- 发布后自动生成 dev Catalog。

只有将隔离服务端迁移到新版 dev `content:sync` 架构并完成验证后，才使用：

```powershell
python wf_publish.py --tables <tables> --layer-placeholders --dev-catalog
```

普通 Mode15 发布不加这两个参数。

## 推荐操作顺序

### 普通发布

```powershell
python wf_publish.py --tables <tables> --list
python wf_publish.py --tables <tables>
```

先 `--list` 确认目标版本、表和路径，再正式发布。

### 增量包整合

```powershell
python wf_pack_consolidate.py list
python wf_pack_consolidate.py plan --from-ver 1.4.54 --to-ver 1.4.59
python wf_pack_consolidate.py build --from-ver 1.4.54 --to-ver 1.4.59
```

整合器只产出候选包，不会自动部署。不要因为已有整合包就删除中间版本旧包；
仍停留在中间版本的客户端需要原链才能升级。

### 整链压缩

```powershell
python wf_chain_squash.py analyze
python wf_chain_squash.py build --tag <唯一标签> --dry-run
```

只有完成以下检查后才能去掉 `--dry-run`：

1. 等价校验通过；
2. 新安装客户端能完整更新；
3. 停留在至少一个中间版本的客户端能更新到链尾；
4. 游戏能登录、进入活动、进入单人和多人玩法；
5. 当前 CDN 和 `asset-patch/active` 已有独立备份。

`retire --yes` 会把旧 zip 移入 retired。即使可用 `undo` 恢复，也必须视为高风险操作，
未经明确要求不得执行。
