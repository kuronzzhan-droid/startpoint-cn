# 玩家登录限流

`player-auth` 路由使用一分钟固定窗口。代理信任仍由 `TRUST_PROXY` 决定；默认忽略请求自带的转发头。Windows portproxy 丢失原始来源地址时，共享来源无法通过 XFF 恢复真实 IP。

| 请求 | 身份限额 | 同一来源总额 |
| --- | --- | --- |
| 登录、注册、绑定、认领、重置密码 | 每个规范化账号名、认领 UID 或凭证各 30 次/分钟 | 300 次/分钟 |
| 恢复、退出有效登录会话 | 每个已验证账号 120 次/分钟 | 1200 次/分钟 |
| 无效会话 | 每个来源 120 次/分钟 | 与会话请求共用 1200 次/分钟 |
| 缺少可用身份的密码类请求 | 每个来源 30 次/分钟 | 与密码请求共用 300 次/分钟 |

成功和失败都计数。账号名大小写归一，绑定同时计账号名与 proof，认领码和重置码共用 code 桶；只有该路由实际消费的字段用于计数。有效会话先通过当前数据库验证，再使用账号 ID，不能仅凭自带 token 获得独立会话预算。来源总额限制轮换账号、随机凭证与无效会话；账号预算限制跨来源尝试同一账号。

账号身份预算是原来的 30/120 次额度；来源总额提供十个密码预算的共享空间及较高的有效会话容量。它减轻正常玩家共用 NAT/portproxy 出口时的冲突，同时维持有限的共享上限；共用来源仍可能达到总额上限。

桶总数最多 8192，容量耗尽时拒绝新桶；过期桶每分钟清理。凭证仅保留 SHA-256 摘要，不保存或输出原始 token、proof、code 或密码。状态仅在当前服务进程内，不是多实例共享限流。

行为检查：`node tools/run-isolated-check.cjs --test tests/player-login-rate-limit.test.cjs`，以及现有登录/本地认领回归。测试使用隔离数据库和 Fastify.inject，不涉及正式存档或公共入口验收。
