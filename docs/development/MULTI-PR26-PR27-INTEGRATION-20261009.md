# 多人联机与 AI 编队整合

## 副本通关池

按副本类别与关卡 ID 分池，每池保留最近通关的 50 名玩家编队，取消高战力保留名额。同一玩家再次通关覆盖此前记录；同毫秒记录按玩家 ID 稳定排序。战力仍是候选筛选门槛，特定蒸汽机器人关卡继续要求对应属性。

录入、启动及重载都执行容量整理，表结构与 JSON 格式不变。只能从现存历史选择最近 50，无法恢复旧策略已淘汰的记录。通关快照仍取自开战前冻结的 TCP 编队，不在结算时重读 SET；普通 SET 扫描已经移除。

## AI 装备准入

普通关卡的历史候选、房间 COM 缓存与房主兜底含幻想专属武器或能力魂时整队拒绝，不卸装后继续使用；幻想关卡保留完整装备。装备解析兼容 TCP Option、普通对象、驼峰与下划线字段，即使可选 Mode15 模块缺失，也保留固定专属 ID 范围识别。

合法 COM 编队在同一房间续战时保持稳定，违规缓存作废后重选。没有合格历史时使用合法房主编队；房主也违规时不填该席位，等实际编队或真人席位变化后重新补席。补席自身的延迟准备回调不会持续重抽同一个无合法队伍的池。

## 五重连接与换场

五重已经进入战斗的连接中途关闭时向队友发送 Leave，避免继续等待已离开成员的帧。连接已发送 Finalize 后的正常关闭不发送 Leave。

换场新增 `BATTLE_LEVEL_NEXT_DEADLINE_MS`，默认 90 秒，处理持续连接但未发送 LevelNext 或 SceneReady 的成员。计时器先让当前轮 I/O 得到处理机会，再进入房间队列校验屏障、房间实例和战斗会话。到期关闭后沿用现有缺席宽限；默认总放行时间约 98 秒。连接已经开始加载的成员继续使用原有加载租约，旧屏障不能影响新场景。

## 战斗诊断

每场联机战斗结束输出一条 `[MULTI-BATTLE]` 摘要，包括屏障等待、席位退休、主线程卡顿、成员入站静默、转发、背压和断线原因。管理端沿用诊断路由的权限边界，新增 `/api/server/diagnostics/battles`；默认保留最近 100 条，可用 `MULTI_BATTLE_TELEMETRY=false` 停用。

最长入站静默涵盖战斗结束、断线和活连接替换前的最后一段；真正离线后的等待不计入连接静默。热路径只计数，不复制战斗包或逐帧打印。

## 范围与交付

整合源为 PR26 `87f056919dc37161657ddc64742aa6a690021c0f`、PR27 `6920c2c462916d06b9db6d88a9b56cbf68c2962c` 的服务端与测试变更；另包含上述保留策略和边界修正。房间清理计时器允许进程自然退出，资源预览测试改用现有 `unzipper`，不增加依赖。

不引入光暗龙能力表重发、对应 ZIP、manifest 版本边、资源生成器或审计。AI 继续使用房主兜底，不新增固定模板作为大厅兜底。玩家存档格式、推荐队伍池与奖励规则不变。

TypeScript 构建通过，多人测试清单的 37 个文件逐项完成隔离回归，另外完成 AI 池持久化、存档兼容、推荐队伍与奖励预览回归。TCP 仿真按实际发送数核对广播和转发，测试结束先关闭数据库再清理；补席回归只推进相关短定时器，保留装备超时门禁，避免把测试时序误判为实现故障。

源码与对应运行产物同步至本地主源码仓库。未启动常驻测试服、未进行客户端实战、未部署云服；具体检查结果与待提交路径在本地任务记录中。必要 `out/` 运行模块受忽略规则影响，后续提交时必须显式加入对应精确路径。
