# 多人重构第二阶段：独立实时所有者

CN 服务入口默认 `MULTI_REALTIME_PROCESS=1`。独立实时进程持有唯一 TCP listener、连接和房间状态，处理战斗转发、场景屏障、冻结名单、续战返回席位与连接租约。业务进程通过有界命令和 JSON 投影访问它；玩家数据库、资格检查、体力支付、活动进度和结算回执继续由业务进程持有。

该阶段继承第一阶段状态契约与延迟统计，客户端 TCP/HTTP 线协议保持兼容。没有修改可玩内容、资源清单、活动时间、玩家存档格式或进度，也没有制作客户端包。源码变化需编译并重启服务后才会加载；本地检查使用隔离数据库和随机回环端口，现有服务未重启。

## 状态与业务归属

| 对象 | 唯一所有者 | 跨进程接口 |
| --- | --- | --- |
| TCP、成员连接、心跳、战斗转发 | 实时进程 | 状态诊断投影；业务事实反向 RPC |
| 房间实例、run、generation、scene、状态版本 | 实时进程 | 带捕获身份的命令和状态投影 |
| SceneReady / LevelNext / Finalize、返回席位、连接租约 | 实时进程 | 开局 Prepare / Commit / Cancel 与持久事件 |
| 大厅、招募、活动集合房间、NPC 战斗席位 | 实时进程 | 父进程验证资格与活动事实，实时进程执行最终准入 |
| 玩家、队伍持久化、支付、奖励、进度、回执 | 业务进程 | 原有玩家事务；有身份和期限的实时开局授权 |
| 准入密钥与登录会话授权 | 业务进程 | 相对有限期限的 socket lease，子进程不复制密钥 |

实时子进程的 `getDb` / `getDatabase` 明确拒绝打开玩家数据库。业务进程访问原房间 manager、SessionManager 或状态修改入口时，权威检查拒绝执行；HTTP 查询结果只有可序列化副本，不携带 socket、Map 或 timer。

业务事实包含 parent epoch、revision、相对有效期和精确任务/队伍作用域。异步 Ready、Start、Enter 和 NPC 准备在返回后再次核对当前连接、房间身份和队伍快照，避免迟到查询覆盖新队伍或新局。Mode15 资格事实未知时阻止新 Ready/Start，保留现有房间；经业务进程确认的普通关卡分类不会因玩家资格缓存过期变成 Mode15 或误解散。

## 开局、换场与持久结果

开局按每次请求建立独立 Prepare claim。普通开局和五王开局均绑定原 instance、run、generation、player、play；五王还校验冻结 run 和对应成员。事务前检查原授权期限、实时 owner epoch 和持久状态。已进入事务的 SQL/支付不因 IPC 超时重复执行。

未决 claim 期间，换场控制帧按接收顺序进入房间有界 FIFO；最后一个明确 Commit/Cancel 后才重放。SceneReady 屏障释放、场景切换与缺席成员到期也遵守同一 claim，防止迟到持久化把已经推进的战局写回旧状态。超时或结果未知不会自动解除 pin，断开的旧连接与替换实例不能借重放获得新局权限。确定回滚只取消本次 claim；匹配原持久 play 的恢复先建立新 pin，再精确对账旧 claim，避免中间无保护窗口。

支付、结算或放弃已持久化后，实时事件经 `durable-owner-event.ts` 发布。丢应用确认时查询原 commandId；只有明确未受理/拒绝后才重发相同 ID、相同内容，不重做 SQL 或换新 ID。处理中仍占预算。重试次数、条数和字节均有限，超过对账范围封闭 owner，保留已持久化数据。年龄上限在调用之间检查，不承诺主进程阻塞时精确到秒的墙钟截止。

命令结果缓存属于进程内有限对账，不能代替跨崩溃持久回执。旧结算/abort 必须绑定原局；旧事件明确不适用时不能修改当前局。五王 TCP proof 等待业务应用确认，未知结果等待原请求的迟到确认；业务失败不会变成有效 proof，finish 不会在未确认 proof 前付款。终局先标记 SETTLED/ABORTED，再释放对应 pin，迟到 Finalize 不能回退终态。

## 续战与失败处理

房主先回房时，未结算/未 Enter 的队友保留原局绑定和个人返回席位。房主 Notify10 或 AI 补位不能消耗这些席位；实际成功 Enter 后才标记 RETURNED。慢队友仍可完成原局支付、取得相同持久回执并返回原房间，旧战斗 CID 不能再作为有效来源。

实时命令 busy、unknown、启动失败或 IPC 关闭返回旧客户端原生临时不可用码 `4050`，不能伪装为“房间已解散”。确定的资格/状态失败继续沿用原业务协议。仅明确未应用的 stale 允许在同 instance/generation 内重新查询一次，不向新局或替换房间追赶，不因 unknown 更换 ID。

socket 授权是有限期限租约，返回时扣除 RPC 已耗时间；刷新等待不能延长原有效期，原期限到达会在实时进程主动关闭连接。换场及战斗心跳的 loading/ready/active 期限由实时进程独立维护。活动上报合并为非阻塞业务 RPC，高频转发不等待玩家数据库。

## 运行开关与故障边界

正常关闭采用停止准入、排空、最终关闭三个步骤。关闭状态保持封闭，迟到定时器和持久事件重试不能重新创建实时进程；仅正常运行期间的显式生命周期启动可建立新 owner epoch。业务进程受理的命令持有与 owner、commandId 绑定的随机授权至真实应用 ACK 或通道终止，调用超时不会提前释放预算或收尾权限。

TCP 业务控制在子进程本地立即执行，并通过有界 FIFO 登记取得父进程授权；后续队伍保存和五王 proof 等待该授权。子进程关闭入口的 ACK 构成登记截止线，之后拒绝新工作。队列、延迟回调、真实反向 RPC、五王 proof 和导出 worker 的实际退出均参与排空。心跳与战斗数据转发无需逐帧登记。关闭时丢弃尚未重放的 pin 控制帧并释放等待，不回退战局或修改持久进度。

- `MULTI_REALTIME_PROCESS=1` 是 CN 默认模式；入口等待子进程 listener 就绪。子进程固定关闭旧 `MULTI_BATTLE_RELAY_PROCESS`，避免再嵌套一个转发进程。
- 显式 `MULTI_REALTIME_PROCESS=0` 保留 embedded 兼容模式；它受主进程阻塞影响，不能使用本阶段隔离结论。
- owner 异常退出、通道故障或发布对账失败后封闭该 owner，断开其连接。业务进程不新建本地权威、不自动重启 owner 或切换 TCP listener；恢复需要显式服务生命周期重启。
- 已持久化支付、存档与回执保留。该阶段没有实现进程崩溃后实时场景重建、跨断线补帧或手机 Resume；不能把持久数据保留写成原战斗可续接。
- 子进程继承日志输出。第一阶段匹配 ID 的 Measurement RTT、相邻 RTT 抖动及超时统计由合成协议探针采集；生产未接入该采集器，不能当作真实客户端统计。现有日志可核对换场屏障、断连、背压和处理时间；owner 命令通道尚未导出 IPC 应用耗时直方图。真实客户端 RTT、抖动与超时统计需要客户端匹配回复并上报，或新增能回显探测 ID 的协议响应，仍待实现与实机验证。

## 本地验证与待验范围

完整联机清单共 68 个唯一文件、421 项 Node 测试执行，最终失败、取消、跳过与 todo 均为零；脚本式测试按 Node 报告的文件执行计数。TypeScript 编译、原联机回归、五王 56 项集成、活动集合房间与支付保护、新边界测试，以及清单外两份隔离 V2 存档兼容检查均通过。首轮五个文件的旧替身未符合新异步准入、真实状态契约或原生临时失败码；只适配相应替身并保留原身份、资格与支付断言，各失败文件定向复测通过，原失败日志保留。重复复测不累加为新的唯一覆盖。

真实远程默认路径使用三个独立进程、Fastify HTTP 命令和回环 TCP：业务进程阻塞约 6.5 秒期间，匹配 Measurement 回声、跨 socket 数据转发、LevelNext / SceneReady 屏障仍由实时进程继续处理，静默成员约 5 秒后按租约关闭。另一组两真人协议连接验证房主先返回、慢队友结算/回执重放/restore/Enter 回原房间，并检查业务进程 listener 为空、直接房间权威读取被拒绝。还覆盖 owner 故障后 native 4050 和无本地 listener 回退，以及独立 child 数据库访问拒绝。

回环小样本只证明此故障注入下的进程隔离，不是云服延迟分位数或真实帧率改善。新握手、资格刷新、支付等需要业务事实的操作仍可能等待业务进程。五重完整多段换场、最终结算、移动网络、客户端画面及云服实测尚未验收；既有断网/重启恢复问题也不能据此宣称解决。
