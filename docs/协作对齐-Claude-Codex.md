## 1. 角色分工

| | Claude | Codex |
|---|---|---|
| **主责** | 设计构想、可行性审查、判断、方案合成、施工规格 | 按规格实现、批量施工、测试 |
| **产出** | 设计文档、任务书、评审意见、拍板材料 | 代码、测试、执行报告 |
| **写码** | 仅限数据表/配置/文档，及**明确授权**的小改（见 8.①） | 全部生产代码 |
| **子代理** | 不主动开；调查类才开，且降级到 opus | 按 superpowers 流程自行决定 |
| **机械扫描** | 用本地脚本，不开 agent | 同 |

**分工原则**：Claude 决定"做什么、为什么"，Codex 决定"怎么写"。
**Claude 不得在任务书里规定实现细节到行级**，除非那是硬约束（例：共享表必须键级改）。

## 2. 事实 / 判断 / 决定 —— 三层标注（强制）

Claude 写给 Codex 的任何任务书、规格、评审，**必须逐条标注属于哪一层**。

| 标注 | 含义 | 必须附带 | Codex 可否质疑 |
|---|---|---|---|
| `【事实】` | 实测得到的客观状态 | **来源 + 时间戳** | ✅ 实测不符时**必须**质疑 |
| `【判断】` | 推理得出的结论 | **置信度**（高/中/低）+ 依据 | ✅ 有反证即质疑 |
| `【决定】` | 已拍板的取舍 | 拍板人（作者 / Claude） | ❌ 不得自行改；有异议先报告 |

**示例**：

```
【事实】merge-base == 76223aa6（`git merge-base` 实测，2026-08-10 23:40）
【判断】M 桶 180 个文件可能基于我方旧状态（置信度：中；依据=对方 CI 已知三处预期红）
【决定】共享表一律键级三向并集，禁止整文件覆盖（拍板：作者；理由=整表读改写回曾致后写者全覆盖）
```

**未标注的任务书，Codex 应退回要求补标注**，不要凭猜测区分。

## 3. 「发现不符就停」条款（强制）

**每份任务书必须包含以下原文**：

> 若实测与本文【事实】不符，**停止并报告，不要自行调整方案**。
> 【判断】被反证时同样停止报告。【决定】有异议时报告，不得自行覆盖。

**理由**：Claude 的判断有确凿的错误历史（详见第 7 节），而 Codex 会忠实执行错误前提。
这条是最便宜的止损——错误不会被放大成一整轮施工。

## 4. 冲突处理协议

| 冲突类型 | 处理 |
|---|---|
| **事实冲突**（双方对同一客观状态说法不同） | **实测为准**。谁的说法与实测不符，谁改。附上复现命令 |
| **判断冲突**（同一事实，结论不同） | **双方都停，报告给作者**。不许任何一方自行覆盖 |
| **决定冲突**（触及已拍板项） | **停**。拍板项只能由作者改 |
| **风格差异**（工作流程、文档节奏不同） | **不是冲突，不处理**。角色不同，风格本就该不同 |

**默认值**：拿不准属于哪类 → 按「判断冲突」处理，即停下来问。

## 6. 文档格式：沿用现有 spec + plan 惯例

**【事实】** 本仓已有 25 份文档采用 superpowers 的 spec/plan 配对格式
（`docs/superpowers/specs/*-design.md` + `docs/superpowers/plans/*.md`，2026-07-05 起，共 15 plans + 10 specs）。
plan 文档头部带 `REQUIRED SUB-SKILL: superpowers:subagent-driven-development / executing-plans`，
正文用 `- [ ]` checkbox 跟踪。

**【决定】格式沿用，但入库范围按作者规则收窄**（作者 2026-08-11 明确）：

> 计划书、执行步骤大概文档**不需要上传仓库**；架构等设计**可以**。

| 产物 | 格式 | 入不入库 |
|---|---|---|
| **设计 / 架构** | `*-design.md`，沿用 specs 惯例 | ✅ 入库 → `docs/superpowers/specs/` |
| **实施计划 / 执行步骤** | 沿用 plan 惯例（Goal / Architecture / Tech Stack / Global Constraints / `- [ ]` checkbox） | ❌ **不入库** → 落 `work/`（已 gitignore） |
| 调查报告、评审意见、交接记录 | 自由 | ❌ 不进 specs/plans（避免长期规格与过程记录混放，见 8.③） |

**理由**：格式沿用是因为存量 25 份 + Codex 已按此工作一个月，换格式成本高。
入库范围收窄是因为计划书是过程产物，寿命短，入库只会稀释长期知识。

> **⚠ 存量不一致（待处理，见 8.④）**：`docs/superpowers/plans/` 现有 **15 份计划书已入库**，
> 与上述规则不符。**不得自行删除**——是清理、迁到 `work/`、还是承认为历史例外，由作者决定。

## 7. 双方共同的硬纪律

以下为**双方都必须遵守**，违反即视为事故：

### 7.0 作者通用工程纪律（原文，2026-08-11 确认对两个执行者同等适用）

> 1. 代码文件注意不要过大，及时拆分；
> 2. 计划书、执行步骤大概文档不需要上传仓库，架构等设计可以；
> 3. 单个模块或功能完成后就 commit 一次；
> 4. 注意代码卫生和 commit 卫生；
> 5. 实施计划任务书等需要审查的文档用中文；
> 6. 不要过度设计，不明确的边界就问我。

**【事实】** 这六条原本只存在于 Codex 侧的全局配置（`~/.codex/AGENTS.md`），
Claude 一直不知道。2026-08-11 作者确认对双方同等适用，故收录于此。

落地要点：

- **第 1 条**已有现成对象：`mod-tools/wf_gui.py` 8842 行、出过两次事故（重名函数静默覆盖、
  删 DOM 致全站白屏）。**新写代码不得再制造同类单文件**；既有大文件的拆分见 8.③。
- **第 2 条**见第 6 节表格。
- **第 3 条**是提交节奏的唯一标准：**完成一个可独立描述的单元就提一次**，
  两个执行者同标准。提交只暂存自己改的文件，**禁止 `git add -A` / `git add .`**
  （仓内长期存在作者未提交 WIP，全量暂存必然误提）。
- **第 6 条**与第 3 节「发现不符就停」、第 8 节「未决项不得自行决定」是同一条纪律的三种表述。

### 7.1 数据写盘

- **共享表（`assets/*.json`、`assets/cdndata/*`）一律键级改，禁止整表读改写回。**
  整表覆盖会让并发的另一方改动全部丢失。
- 动手前查 `mod-tools/work/sync_pending.json`：**非空 = 作者正在建角色，只读不写盘。**
  （注意盘上有多个同名文件，权威的是 `mod-tools/work/` 下那个。）
- **不新增 `.bak-*` 文件当版本控制**，用 git。已有的不删，但不再产生新的。
- 用户 WIP（已修改的 `assets/*.json`、`work/`、未跟踪角色方案文档）
  未证明归属前不覆盖、不还原、不提交，不得 `git clean` 批量处理。

### 7.2 判断纪律

Claude 侧有确凿的误判历史，以下为强制自检——**Codex 发现对方违反时应指出**：

| 规则 | 反面教材（真实发生） |
|---|---|
| **说"官方没有 X"必须同时给出搜索面**（搜了哪些名字/表/层）。给不出就说"我没找到" | 属性免疫：只搜 `ElementResistance` 得出"零先例"，实际 `ACToleranceOfElement` 有 545 处 |
| **说"官方是这样"必须点名基线来源**。`store/` **永远不算**官方基线（混着自制改动） | 拿自制 ability_soul 当基线，得出错误的"充能上限 50%" |
| **方向性结论（大/小、上/下、加/减、上取整/下取整）必须用已知实例反推验证** | 连战塔曲线取档方向判反，**错的方向还被写进了测试断言** |
| **引用代码前确认该路径在目标场景真的会执行** | 属性免疫据未执行的代码路径判错并真机翻车 |
| **一条证据不下结论，否定结论尤其** | 技能槽最大值判错两次 |

### 7.3 发布与验收

- 新角色整包走 `mod-tools/wf_character_flow.py`（37/37 资产、manifest/hash/seal、三层一致）；
  普通单表修改才走 `wf_publish.py`。
- 资产整理必须 `scan → plan → preflight → quarantine → verify → restore drill`。
  **隔离 ≠ 删除**；`purge` 需单独授权和精确确认口令。
- 改 `src/` 后必须 `tsc`，否则服务端跑 `out/` 里的旧产物。
- **静态检查不等于验收。** 涉及新表/新路由的改动，需起服打一个低副作用探针。
- 上游 `origin` 的 push 已锁（`DISABLED_UPSTREAM_NO_PUSH`）。
  推送一律去 `fork`。需要给上游提 PR 时向作者申请解锁。
