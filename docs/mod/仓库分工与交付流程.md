# 仓库分工与交付流程

2026-10-24 定。三个仓库各管一段，按「工具 → 产物 → 服务端」的顺序流动。

| 仓库 | 管什么 | 不放什么 |
|---|---|---|
| [startpoint-cn-mod-tools](https://github.com/kuronzzhan-droid/startpoint-cn-mod-tools) | 所有制作工具：编辑台、平衡包、角色包、卡池/活动内容、发布流水线、Wiki 生成器与前端 | 服务端代码 |
| startpoint-cn（本仓库） | 测试服（175）：服务端代码、生成好的服务端数据、补丁链清单、APK 补丁源 | 新的制作脚本（新工具写进 mod-tools） |
| [Ku1o/startpoint-cn-kulo](https://github.com/Ku1o/startpoint-cn-kulo) | 正式服，由灰维护 | — |

本仓库的目录结构（`tools/`、`client-patch/`、根目录启动脚本等）与 kulo 保持一致，方便灰直接拉取，所以不在这里单方面重排。`tools/` 下已有的一次性集成目录保持原样，新的制作工具一律进 mod-tools。

## 测试服 → 正式服

1. 每个改动照常在测试服上线：本仓库 main、Release `patches-<版本>`、[测试服与正式服差异.md](测试服与正式服差异.md) 记一行。
2. 不再每个版本单开一个 kulo draft PR。按活动或版本段，从本仓库开 `release/<活动名或版本段>` 分支，对 kulo 开**一个** PR，正文列出：
   - 包含的版本号范围；
   - 差异表里对应的行；
   - 对应的 Release 补丁包链接和 SHA256；
   - 只属于测试服、不要合并的部分（见 [测试服专用设置.md](测试服专用设置.md)）。
3. 什么时候上正式服，由作者和灰商量决定。
