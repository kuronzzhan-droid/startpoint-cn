# 灰怎么拉取（正式服同步）

以后正式服直接从本仓库拉取，不再单独做分享包。本仓库 main = 测试服现状（服务端代码、服务端数据、补丁链清单），补丁包和 APK 补丁源码分别在 Release 和 `apk-patches/`。

## 1. 拉代码

本仓库 main 已合并 kulo main（Ku1o/startpoint-cn-kulo `224aa2a6`），所以和 kulo 的差异就是我们的改动：

```bash
git remote add zzh https://github.com/kuronzzhan-droid/startpoint-cn.git
git fetch zzh main
git diff origin/main zzh/main -- src tests scripts package.json   # 服务端代码改动
```

更省事的做法是直接用分好类的补丁（都相对 kulo main `224aa2a6`）：

| 补丁 | 内容 | 正式服 |
|---|---|---|
| [01-server-fixes-and-features.patch](kulo-patches/01-server-fixes-and-features.patch) | 结算回执防二次发奖、超限 Lv120、进程守卫、/load 无变化不开写事务、实时联机子进程自动重建等 | 可以用 |
| [02-test-server-only.patch](kulo-patches/02-test-server-only.patch) | 共享测试密码建号、单人分数缩放、人机复制房主、补丁分流、准入诊断日志 | **不要用** |
| [03-server-assets.patch](kulo-patches/03-server-assets.patch) | 服务端数据（新角色、超限表、平衡文本、领主战/共同决战、武器等） | 可以用 |

```bash
git apply --check docs/mod/kulo-patches/01-server-fixes-and-features.patch
git apply docs/mod/kulo-patches/01-server-fixes-and-features.patch
```

测试服专用的东西见 [测试服专用设置.md](测试服专用设置.md)。特别注意：如果整体合并了 main，单人分数缩放默认会按 0.5 缩，要么去掉那段代码，要么在 `.env` 里写 `SINGLE_SCORE_SCALE=1`。

## 2. 拉补丁包

- `assets/asset-patch/manifest.json` 是测试服链（尾 1.4.224）。
- 补丁 zip 不进 git，在 Release：
  - [patches-1.4.224](https://github.com/kuronzzhan-droid/startpoint-cn/releases/tag/patches-1.4.224)：1.4.220–1.4.224
  - [patches-1.4.219](https://github.com/kuronzzhan-droid/startpoint-cn/releases/tag/patches-1.4.219)：1.4.219
  - [snapshot-1.4.218-20261016](https://github.com/kuronzzhan-droid/startpoint-cn/releases/tag/snapshot-1.4.218-20261016)：kulo main 没有的 1.4.131–1.4.218
  - kulo main 已有的包就在仓库 `assets/asset-patch/active/`
- 下载后放进 `assets/asset-patch/active/`，每个 Release 都附 `SHA256SUMS.txt`。
- 正式服现在在 1.4.136。之前给的 [分享包 1.4.136→1.4.220](https://github.com/kuronzzhan-droid/startpoint-cn/releases/tag/hui-share-1.4.220-20261016) 是一步到 220 的合并边，用它到 220 后，再按本仓库 manifest 接 1.4.221 起的边。
