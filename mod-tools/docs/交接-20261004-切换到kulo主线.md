```powershell

git push origin archive/release-modes-20260714 archive/characters-1.4.407
```

**1.2 镜像 `main` 和 `staging`**（`main` 是快进，不需要强推；首次约 1 GB，会慢）

```powershell

git push origin kulo/staging:refs/heads/staging
```

停止条件：
- `main` 推送报 `non-fast-forward` / `rejected` → 说明你的 `main` 被别人改过。**不要加 `--force`**，先查清楚。
- 传输中途断开 → 再执行一次同样的命令即可（已传的不会重复）。

**1.3 核对**

```powershell
git ls-remote origin refs/heads/main refs/heads/staging "refs/tags/archive/*"
git rev-parse kulo/main kulo/staging
```

`origin` 的 `main` / `staging` 必须分别等于 `kulo/main` / `kulo/staging`。

**1.4 GitHub 网页**：你的仓库 → Settings → General → Default branch → 改成 `main`。

**以后同步镜像**：在旧目录 `git fetch kulo`，再跑一遍 1.2（都是快进）。

## 6. 日常开发流程（速查）

**6.1 一个任务一条分支、一个 PR**（`CONTRIBUTING.md`）

```powershell
cd D:\WF\startpoint-cn-kulo
git fetch origin
git switch -c feat/<简短主题> origin/staging     # 前缀：feat/ fix/ perf/ docs/
# ……修改……
npm run typecheck
npm run build                                    # 生成 out/
git add <逐个明确路径>                            # 禁止 git add . / git add -A
git add -f out/<新增的对应 .js>                    # out/ 被 .gitignore 忽略，新文件必须 -f
npm run check:out                                # 检查每个改动的 src/*.ts 都带上了对应 out/*.js
bash scripts/check-hygiene.sh --all              # 与 CI 同款卫生检查（需要 Git Bash）
git commit                                       # 标题 + 正文；按 server / cdn / client 分类
git push -u origin feat/<简短主题>
```

然后在 GitHub 开 PR：**base 选 `staging`**，按模板填「目标 / 范围与影响层 / 改动说明 / 验证 / 风险与回退 / 边界检查」。验证里只写实际跑过的命令和结果。需要产品决定的问题在 PR 里列为「待所有者确认」，不要自己假设。

**6.2 跟上 `staging`**：他自己直接往 `staging` 推，你的分支要常同步。

```powershell
git fetch origin
git rebase origin/staging
```

`out/` 出冲突**不要手合**：先解决 `src/` 冲突 → `npm run build` → `git add`（新文件 `-f`）对应的 `out/` → `git rebase --continue`。变基后推自己的分支用 `git push --force-with-lease`（只限自己的临时分支）。

**6.3 硬规则**

- 不直接推送、强推或删除 `main` / `staging`；不自行合并。
- 不提交密钥、`.env`、`config/`、APK/IPA/SWF、数据库、日志、签名材料；不改 `.cdn/`。
- **写库**：新代码一律 `await runPersistenceTransaction({ domain, playerId, operation }, …)`；不直接 `db.transaction()`；新路由不新增 `…Sync` 入口。domain：单人副本 `single-quest`、活动 `event`、联机结算 `multi-settlement`；要新增 domain 先和他商量（#13）。
- **保护范围**（改之前先问他，#12）：`src/multi/tcp/**`、`src/multi/coordinator/**`、`src/multi/room/**`、`src/multi/state/**`、`src/multi/index.ts`、`src/workers/**`、`src/lib/persistence-coordinator.ts`、`src/lib/sqlite-*`、`src/cn-server.ts` 启动/关停、存档快照相关共享文件。他宣布重构冻结窗口时，暂停联机、房间、结算相关改动（#16）。
- **资源**：只出候选包到 `assets/asset-patch/active/candidates/`，标 `candidate_only`。PR 里必须附：基线版本或提交、ZIP 与成员哈希、内容清单、改了哪些表和资源、服务端/客户端影响、存档影响、测试范围、已知限制（#5、#6）。不复用旧链版本号（#7）。
- **上线**：他部署。普通内容观察一个完整回归窗口；持久化、联机、客户端联动观察 24–48 小时（#18）。
